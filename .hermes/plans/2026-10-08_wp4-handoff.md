## Method

1. **Classify data, don't decode it.** A byte histogram over the chunk settles most
   cases: tilesets show ~80-160 distinct values with no long runs; raw filler here is
   long `00` runs (see the WP3 filler blocks in `home.asm` for what that looks like
   typed out). Length being a multiple of 16 is evidence for 2bpp tiles, not proof.
2. **Prefer extraction over `db` when a neighbour has a name.** The project convention
   is `gfx/<dir>/<name>.2bpp`, `tilemaps/<dir>/<name>.bin`, `levels/levelNN.bin`, all
   byte-for-byte `INCBIN`s of the ROM. `git ls-files | grep -c gfx` shows 80 such files
   already. Extraction is a `dd` from `baserom.gb`; because the file is then `INCBIN`ed
   at the same place, byte-identity holds by construction.
3. **Keep the existing `UnknownData_0xNNNNN:` label** whenever a chunk stays inline as
   `db`, so any cross-bank pointer that already targets it keeps referring to something.
4. **Add a `;unused filler` comment only when the bytes really are filler** (long runs
   of one value). Do not label real data as filler.
5. **One bank per batch**, `make clean && make compare` after each, revert the bank if
   `cmp` fails. Never hand off a red tree.

### Tools available

`sm83.py` (SM83 decoder), `addrmap.py` (line→address map by `PRINTLN @` probe) and
`gen.py` (the WP3 chunk generator) are saved in **`.hermes/tools/wp3/`**. `gen.py` is
bank-0-specific (its `SPEC` and label tables are hard-coded for `home.asm`); for WP4
reuse `sm83.py` and `addrmap.py` and write a small per-bank `SPEC`. Notes:

- `addrmap.py` rewrites `SECTION "bank00", ROM0` to `ROM0[$0000]` and cuts `main.asm`
  after the home include. For a banked target section, keep the section as-is if it is
  floating (in RGBDS `@` in a floating section is the offset within the section, which
  is what you want) or rewrite it to `ROM0[$0000]` if you hit an "address not constant"
  error.
- Inject `PRINTLN "N<line> ", @` before every top-level line and never inside a
  `MACRO`/`ENDM` body, and never before the first `SECTION`.
- A `.sym` file goes stale: regenerate with
  `rgblink -n sml2.sym -o /dev/null main.o` before each batch, or the generator will
  re-create labels that the previous batch already added.

### Encoding constraint (RGBDS v1.0.4) — applies to every edit

The automatic `LD` -> `LDH` conversion was removed in RGBDS 0.8.0: for any address in
`$FF00-$FFFF` the mnemonic decides the size, so `ldh [x], a` is 2 bytes and `ld [x], a`
is 3. Keep whichever form the ROM already uses; never let a symbol rename change the
size. A change of size shifts every following label, so `cmp` reports thousands of
differing bytes rather than a local diff. Also: `ldh [$FF41], a` must keep the full
`$FFxx` address — the `$00-$FF` short form was removed in 1.0.0.
