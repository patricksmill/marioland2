## The level layout format — what is VERIFIED

`home.asm` bank `$00`, `UnknownCall_0x0361` → `Read_Level_Data: ;$0386`:

```
UnknownCall_0x0361:
    ld hl, $42F0
    ld a, [$A812]
    and $0F
    sla a
    ld e, a
    ld d, 0
    add hl, de            ; hl = $42F0 + ($A812 & $0F) * 2
    ld a, [hli]
    ld e, a
    ld a, [hl]
    ld d, a               ; de = dw pointer from the table at $42F0
    ld hl, $0000
    ld a, 10
    ld [hl], a            ; SRAM enable
    ld h, 64
    ld a, 0
    ld [hl], a            ; RAM bank 0
    ld h, 96
    ld a, 1
    ld [hl], a            ; RAM banking mode
    ld hl, $B000          ; destination in RAM

Read_Level_Data:
    ld a, [de]
    inc de
    bit 7, a
    jr nz, .compressed
    ld [hli], a           ; bit 7 clear: literal byte
    ...
.compressed:
    and $7F               ; control & $7F = value
    ld [hli], a
    ld c, a
    ...
    ld a, [de]
    inc de
    ld b, a               ; next byte = repeat count
.decompress:
    ld [hl], c
    inc hl
    ...
    dec b
    jr nz, .decompress
    jr Read_Level_Data
.checkRAMbounds:
    ld a, h
    cp $E0
    jr nz, Read_Level_Data
    ret
```

**Format (verified):** plain RLE. Control byte `c`:
- `c & $80 == 0` → output `c` literally.
- `c & $80 != 0` → output value `c & $7F`, repeated `n` times, where `n` is the **next
  byte**. The loop is `dec b / jr nz`, so **`n = 0` means 256 repeats, not 0** (a
  decoder must simulate the loop, not use `n == 0 → skip`).
- Output goes to `$B000` and stops when `h == $E0`, i.e. **exactly `$3000` bytes**
  (`$B000`–`$DFFF`); the check happens on every byte at each 256-byte boundary, so a
  run may be cut mid-way and the input is consumed partway through a token.

**Verified stream addresses:** the 16 `dw` entries at ROM `$42F0` are
`$0800, $6108, $0800, $6210, $0800, $6318, $0800, $6420, $1000, $7000, $1000, $7108,
$1000, $7210, $1000, $7318`. The eight values `$6108 $6210 $6318 $6420 $7000 $7108
$7210 $7318` all lie in **bank `$01`** (spacing `$108`, except the `$6420 → $7000`
gap) and each decodes to exactly `$3000` bytes, consuming only 156–292 input bytes.
**Those are the level layout streams, and they live inside bank `$01`'s two big
chunks** (`$5E42`–`$6442` and `$6529`–`$8000`). The interleaved `$0800`/`$1000` entries
are unresolved (the routine reads a single `dw` per index, so either the index
semantics or those entries' role is still open).

## Method

1. **Do not disassemble data.** For each chunk, first classify (byte histogram +
   render as 2bpp tiles if graphic + `sm83.py` linear sweep + neighbour diff), then
   choose: code → disassemble; data → `db`/`dw` or extract; RLE stream → decode.
2. **Code chunks:** extend the WP3 generator (`.hermes/tools/wp3/gen.py`) to banked
   sections — its `SPEC` and label tables are bank-0-specific. A chunk whose bytes
   sweep to a coherent routine ending in `ret`/`reti`/`jp` is code; a chunk with
   illegal opcodes or repeated small values is data.
3. **One bank per batch**, `make clean && make compare` after each, revert the bank if
   `cmp` fails. Never hand off a red tree.
4. **Keep `UnknownData_0xNNNNN:` labels** on anything left inline as `db`.

### Tools available
`sm83.py` (SM83 decoder), `addrmap.py` (line→address map via `PRINTLN @`), `gen.py`
(bank-0 chunk generator) in **`.hermes/tools/wp3/`**; `wp4.py` (per-bank chunk
replacement: extract/db/level-tail) in **`.hermes/tools/wp4/`**.
- `sm83.py`'s `SYM` path (`/home/pmill/.hermes/cache/scratch/sml2.sym`) and `load_syms`
  only read **bank 0** labels; extend it for banked work.
- `addrmap.py` rewrites `SECTION "bank00", ROM0` → `ROM0[$0000]` and cuts `main.asm`
  after the home include. For a banked target section, keep it floating (in RGBDS `@`
  is the within-section offset, which is what you want) or rewrite to `ROM0[$0000]`.
- Regenerate the symbol table before each batch or the generator re-creates labels the
  previous batch added:
  `rgblink -n sml2.sym -o /dev/null main.o`.

### Encoding constraint (RGBDS v1.0.4) — applies to every edit
The automatic `LD`→`LDH` conversion was removed in RGBDS 0.8.0: for any address in
`$FF00-$FFFF` the mnemonic decides the size, so `ldh [x], a` is 2 bytes and `ld [x], a`
is 3. Keep whichever form the ROM already uses; a size change shifts every following
label and `cmp` reports thousands of differing bytes. `ldh [$FF41], a` must keep the
full `$FFxx` address.
