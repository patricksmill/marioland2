## The one method that works (every batch)

1. Decode semantics — statically, and live (PyBoy) whenever a name is ambiguous.
2. Add `DEF sName EQU $Axxx` lines to `ram.asm`, sorted by address.
3. Substitute:
   - bracketed refs only (`[$A2xx]`) with `.hermes/tools/wp6/sub_refs.py <batch.tsv>`;
   - immediate operands (`ld hl, $ADxx`) with `.hermes/tools/wp6/sub_imms.py <batch.tsv>`
     (comment-safe: never touches the part after `;`). Pre-screen: for every address,
     `grep -o "\[\$Axxx\]" | wc -l` must equal the total ref count, else inspect the
     unbracketed sites first (batch 5 pattern: bare sites are `ld hl/de, $AFxx`).
   Batch TSVs are kept in `.hermes/tools/wp6/` (`batch2.tsv` … `batch5.tsv`,
   `batch5_imms.tsv`).
4. `make clean && make compare && sha1sum baserom.gb sml2.gb` — commit ONLY on green,
   with the decoded semantics + live-verification notes in the commit message
   (write it to a file and use `git commit -F`; `$`-words inside double quotes get
   shell-eaten).

### The object/actor system (decoded at `d59ac92`; use this, don't re-derive)

- **Table**: `$AD00-$AEFF`, 16 slots x $20 bytes. Cleared by `$EC31` (bank 3;
  trampoline `$3A00`); `$EC40` clears the `$AFxx` scratch page ($AF00-$AFFF, 256
  bytes; `$3A28` trampoline). `$EC4B` resets the stream ptr to `$AB06`.
- **Slot layout** (offsets from slot base; base = state-byte low & $F0, so the state
  byte lives at +8):
  - `+0/+1` — world X (hi,lo) — for stream spawns seeded from the record key, then
    updated as the object moves (verified live: a spawned enemy walked $D8 -> $C4);
  - `+3/+4` — world Y (hi,lo) — seeded from the camera for script-registered objects;
  - `+5` — sprite-anim index (staging $FFD5); `+6/+7` — link pointer (stream record+2
    for stream objects; the registering slot's base for script objects);
  - `+8` — **state** (0=empty, 1=fresh/standby, 2+=active);
  - `+9` — Y, `+10` — X (screen coords; what the interaction passes box-check);
  - `+11` — sprite id (staging $FFDB); `+13` — attr/frame byte (staging $FFDD);
  - `+17`/`+18` — type parking pair: scripts move the type to +17 while state==1 and
    back to +18 when active (81F7 swaps +17 -> +18; 828F parks +18 -> +17 and zeroes +18);
  - `+18` — **type** (interaction class, when active); `+19..+22` — hitbox top/bottom/
    left/right offsets; `+23` — interaction flags (bit1 = actor-in-box hit $5B6A9,
    bit3 = skip-marker for `$2D7D`, bit4 = touched, bit5 = bumped);
  - `+24..+31` — scratch ($FFE8/$FFE9 counters, $FFEC timer...).
- **Type bits** (`sObjectType`): bit7 = item (`& $7F` -> `sPendingItemId` via `$2DC6`),
  bit6 = harmful ($2E6F damage path), bit5 = standable (top-hit -> `sMarioOnObject`,
  no star-kill), bit2 = message ($3007), bits0/1 = bounceable top ($2E23 ->
  `sObjectBounce`).
- **Stream spawner**: the level's object stream is copied to `$AB06` at load
  (`$EBBB`, bank 3); $AB00-$AB05 hold $FF filler, so the first record is at $AB06
  (level 0: `01 D8 00 01 F0 09`). Records are 6 bytes: `[0]` = X key hi, `[1]` = X key
  (the spawn cursor must equal the pair EXACTLY; the cursor steps in 8px units while
  `$AF01` = camera+112 & $F8, so record keys are 8-aligned), `[2]` = flags (set to 2
  when spawned; easy-mode variant checked with `& $0F` vs `& $0E`), `[3..5]` =
  payload (anim index in `[5]`). The driver `$8C31` (called from the `$812E` loop)
  advances the cursor; `$8D01`/`$8D05` walks the matching record and spawns it into
  the first slot with state 0 (scan starts at `$AD08`, step $20): copies 6 bytes to
  slot+0..+5, slot+6/+7 = record+2, slot+8 = 1, zeroes +9..+31, `$AF40`++ (standby).
- **Template loader**: `$8E6C` copies 18-byte defs to slots 0..$AFC1 (`$AD05`, then
  `$AD25`+$20k) from pointer tables `$4E9A`/`$4EAC` indexed by `$AFC0` (level/boss
  index); config at `$4E3F` -> `$AFC1` count, `$AFC5`, `$AFCA`. Reached via the
  `$3C94` trampoline -> `$8D9C` (clear + load), called from `$0EB0` (level intro)
  only when `sSceneState & $0F != 0` (live: level 0 skips it — no templates,
  `$AFC1` stayed 0).
- **Interaction passes** (bank 0, all step $20 until h == $AF):
  - `$2D7D` Mario-vs-object: `$2EDD` box check (`sMarioObjectYDelta` < $0C = top hit)
    -> `$2DC6` outcome (item / bounce / stand / damage via `$2E6F`; star-kill `$2EAA`).
  - `$2F72` block-bump pass (called from the brick-bump spawn `$5997`): `$2FAE`
    sets slot flags bit5, `$A247`, and `$A256` for type-$80 objects.
  - `$2FED` fireball pass (called from the fireball renderer): `$3007` box check vs
    `$FFC4`/`$FFC5`, sets `$A246`.
- **Update loops** (bank 2): normal gameplay = main loop `$0652` -> `$8000` (box
  setup `$8000`-`$80B7` + per-slot state machine `$812E`: `$81F7` 1->2 activation,
  `$828F` park (2->1 outside the Y keep-alive window), `$826D`/`$818D`, 32-byte
  staging copy to `$FFD0` via `$81A7`/`$81BD`). Cutscene mode
  (`sSceneState & $F0`) = `$3C9F` -> `$8DA9` slot sweep (`$AFC2` counter).
- **Scene system writes slots 1/2 directly** (`$9FF2`/`$A159`/`$A171`): Y/X/sprite at
  `$AD29`+0/+1/+2, using `$AD2F`/`$AD4F` (+15) as in-use gates; `$AFCB` alternates.
- **Camera window summary** (`$8000`-`$80B7` recomputes every sweep from
  `$FFC8/$C9` = camera Y, `$FFCA/$CB` = camera X; `$FFC0/$C1` = Mario Y,
  `$FFC2/$C3` = Mario X): activation = camera +/- $60 X/Y; scan sources = camera
  +/- $70 X; keep-alive = camera +/- $A0 X/Y. `$AF30-$AF33` = Mario (X+8, Y+32).
