# Super Mario Land 2 Decompilation Plan & Model Handoff Guide

## Goal
Bring `sml2decomp` from 60.74% disassembly to 100% complete byte-identical disassembly with RGBDS v1.0.4 compatibility, structured into modular handoff packages partitioned between lightweight (fast/cheap) and high-intelligence models to optimize context windows.

---

## Context Window & Model Tiering Strategy

To prevent context degradation and token exhaustion, work is split into self-contained **Work Packages (WPs)**. Each WP has:
1. A designated **Model Tier** (Lesser AI vs. Intelligent AI).
2. **Entry Criteria & Context Files** to inject into a fresh session.
3. **Exit Gate:** An exact shell command (`make compare` / `cmp`) that must pass before committing and handing off.

### Model Tier Matrix
| Tier | Recommended Models | Best Suited Tasks | Verification Style |
| :--- | :--- | :--- | :--- |
| **Tier 1: Fast / Mechanical AI** | Gemini Flash, Claude 3.5 Haiku, GPT-4o-mini | Syntax migrations, macro updates, hardware equate substitution, pure linear disassembly replacement, file splitting, mechanical regex refactoring | Deterministic `make compare` (pass/fail) |
| **Tier 2: High-Intelligence AI** | Gemini Pro / Claude 3.7 Sonnet / o1 / GPT-4.5 | Control flow analysis, dynamic jump tables (`rst $28`), tile/map RLE decompression reverse engineering, Mario physics & state machine reconstruction, WRAM struct design | Semantic analysis + `make compare` |

### Global Encoding Constraint (RGBDS v1.0.4) — applies to EVERY Work Package

> **The automatic `LD` -> `LDH` conversion no longer exists** (deprecated in RGBDS
> 0.7.0, **removed in 0.8.0**). This is the most dangerous difference between the
> old toolchain and v1.0.4, and it is a live hazard in every package below: the
> ROM uses the 2-byte `LDH` form at most `$FF00-$FFFF` access sites, but v1.0.4
> now emits the 3-byte general form for a plain `LD`.
>
> | Written in source | Bytes emitted by v1.0.4 | ROM form |
> | :--- | :--- | :--- |
> | `ld [rLCDC], a` | 3 | `EA 40 FF` (general `LD [n16],A`) |
> | `ldh [rLCDC], a` | 2 | `E0 40` (`LDH [n],A`) |
> | `ld a, [rIF]` | 3 | `FA 0F FF` |
> | `ldh a, [rIF]` | 2 | `F0 0F` |
>
> **Rule:** for any address in `$FF00-$FFFF`, the **mnemonic** decides the size —
> not the address being a named symbol. Introducing a symbol does NOT imply `ldh`.
> Equates that resolve into that range (`hKeysHeld = $FF80`, `hKeysPressed = $FF81`
> in `ram.asm`) are subject to the same rule. Never convert a 2-byte `ldh` into a
> plain `ld`, and never name a site in a form that changes its size.
>
> Also removed: `LDH [n8],A` / `LDH A,[n8]` (address written as `$00-$FF`) went away
> in 1.0.0, so it must be spelled `ldh [$FF41], a`, never `ldh [$41], a`.
>
> **A size change always shows up as a large downstream byte diff, not a local one:**
> it shifts every following label, so `cmp` will report thousands of differing bytes
> starting at the culprit. Run `make clean && make compare` after every batch and
> revert the batch if `cmp` fails.

## Standard Session Handoff Protocol

When transitioning between sessions or models:
1. **Verify Exit Gate:** Run `make clean && make compare` on the current branch. **Never hand off broken state.**
2. **Commit Clean Work:** `git commit -m "<clear summary of completed slice>"`.
3. **Start Fresh Session:** Launch a new context window with the specific **Handoff Prompt** provided for that Work Package.

## Work Package 1: Toolchain & Syntax Modernization (RGBDS v1.0.4)
**Assigned Model:** **Tier 1 (Fast / Mechanical AI)**  
**Prerequisites:** Base ROM installed at `baserom.gb` (SHA-1: `bba408539ecbf8d322324956d859bc86e2a9977b`).  
**Files Touched:** `Makefile`, `macros.asm`, `ram.asm`, `home.asm`, `main.asm`.

>
> Two details in the steps below are **wrong**; the corrected values are:
> - The release asset is **`rgbds-linux-x86_64.tar.xz`** (flat tarball, binaries at
>   top level), not `rgbds-1.0.4-x86_64-linux.tar.xz` — the URL below 404s. Also
>   `/usr/local/sbin` shadows `/usr/local/bin` on PATH, so install to **both**.
> - `ram.asm` has **33** equates, not 35.
>
> Two migrations the steps below did **not** anticipate were required, and any
> redo must include them:
> - `add de` / `add bc` -> `add hl, de` / `add hl, bc` (**322** sites). v1.0.4
>   rejects the omitted-HL form outright.
> - **The removed automatic `LD`->`LDH` conversion** (see the global constraint
>   section above): 3,627 `[$FF00+$xx]` accesses plus 52 `[hKeys*]` accesses had to
>   become `ldh`. Without this every following label drifted and the ROM could not
>   match. The two `JR` out-of-range errors were purely an artifact of that drift
>   and needed no source fix.

### Step-by-Step Tasks
1. **Install RGBDS v1.0.4:**
   ```bash
   curl -sL https://github.com/gbdev/rgbds/releases/download/v1.0.4/rgbds-1.0.4-x86_64-linux.tar.xz -o /tmp/rgbds-1.0.4.tar.xz \
     && sudo tar -xJf /tmp/rgbds-1.0.4.tar.xz -C /usr/local/bin/ rgbasm rgblink rgbfix rgbgfx \
     && rm -f /tmp/rgbds-1.0.4.tar.xz && hash -r
   ```
2. **Migrate `macros.asm`:** Replace `name: MACRO` label definitions with `MACRO name`:
   ```rgbasm
   MACRO ldh_n_a
       db $EA, \1, $FF
       ENDM

   MACRO ldh_a_n
       db $FA, \1, $FF
       ENDM
   ```
3. **Migrate `ram.asm`:** Prefix all 35 equates with `DEF <name> EQU <val>`.
4. **Replace Obsolete Instructions:** Swap 7 instances of `jp [hl]` to `jp hl` (2 in `home.asm`, 5 in `main.asm`).
5. **Add `clean` to `Makefile`:**
   ```makefile
   clean:
   	rm -f $(objects) sml2.gb
   ```

### Exit Gate


## Work Package 2: Hardware I/O Equate Normalization
**Assigned Model:** **Tier 1 (Fast / Mechanical AI)**  
**Prerequisites:** Work Package 1 complete (`make compare` passing under RGBDS v1.0.4).  
**Scope:** **Re-scoped after WP1.** The raw `[$FF00+$xx]` accesses no longer exist —
WP1 already rewrote 2,073 of them to `ldh [$FFxx], a`, 1,554 to `ldh a, [$FFxx]`, and
52 `hKeys*` accesses to `ldh`. WP2 is therefore a **pure naming pass**: substitute
`hardware.inc` symbols for the remaining numeric `$FFxx` literals while **keeping the
existing mnemonic so the byte size never changes.** 102 distinct `$FFxx` addresses
remain.

### Tasks
1. Add standard `hardware.inc` (from `gbdev/hardware.inc`) under `include/` or project root.
2. Include `hardware.inc` in `main.asm`.
3. Replace numeric addresses with standard symbols, **preserving the mnemonic**:
   - `ldh [$FF40], a` -> `ldh [rLCDC], a`  (2 bytes — **never** `ld [rLCDC], a`)
   - `ldh a, [$FF42]` -> `ldh a, [rSCY]`
   - `ldh a, [$FF43]` -> `ldh a, [rSCX]`
   - `ldh [$FF47], a` -> `ldh [rBGP], a`;  `[$FF48]` -> `[rOBP0]`, `[$FF49]` -> `[rOBP1]`
   - `ldh [$FF00], a` -> `ldh [rP1], a` / `ldh [rJOYP], a`
   - `ldh a, [$FF44]` -> `ldh a, [rLY]`;  `ldh [$FF0F], a` -> `ldh [rIF], a`;
     `ldh [$FFFF], a` -> `ldh [rIE], a`
4. Batch per register and verify after each batch.
5. **Leave the 324 `ldh_n_a` / `ldh_a_n` macro call sites alone.** They deliberately
   emit the 3-byte `db $EA/$FA, n, $FF` form. If you name one, use the **no-`ldh`**
   form (`ld [rX], a`) so it stays 3 bytes.
6. Verify with `make clean && make compare` after each batch and revert any batch
   that changes the size.

### Exit Gate
```bash

```
